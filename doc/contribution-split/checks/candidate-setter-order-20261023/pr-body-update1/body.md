Candidate labels can disappear during accessibility-node inspection when custom drawing uses private text while the framework TextView still has an empty text/Layout. This one-file patch keeps framework text as the single value and synchronizes its Layout before custom sizing and drawing.

After investigating review comment 4354993843, `7f909060` simplifies the setter to call `super.setText(charSequence, bufferType)` as its first statement, without a condition. It then unconditionally marks the custom measurement/transform caches dirty and requests layout/redraw. No old-content read or equality guard remains. The parent handles constructor initialization, null and same-content BufferType conversions; the override never touches uninitialized paint caches.

I traced the API21/API35 TextView paths and current label consumers. Ordinary relayout/invalidation requests subsequent traversal, and these consumers do not register synchronous text callbacks that measure/draw during the parent setter. No current-path reason for dirty-before-super was found. This removes the previous equal-content optimization; repeated-assignment performance has not been measured. `super.onMeasure` remains for framework Layout/accessibility; the extra `super.onLayout` forwarding remains removed.
