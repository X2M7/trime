## 1. 验收范围

本轮以旧版 17 项业务定义为基线：`trime` 与 `tongwenfeng` 两个内置主题各执行 C1–C8，再执行 1 项 `tongwenfeng` 符号类别宏回归。行为说明来自 `doc/t9-input.md`：九键方案为 `luna_pinyin_t9`，使用现有 `luna_pinyin` 词典及用户词典；2–9 输入拼音，长按数字输入字面数字；数字/符号页为字面模式；返回默认布局后恢复当前方案；切换编辑器会结束当前可见组合并清除拼音锁定。

## 6. rebase 后真机补测

这些检查针对新上游行为，必须使用 rebase 后候选 APK。

### R1 Return 标签与动作

在键盘不重启的情况下依次聚焦：空多行框、带 Send/Search/Done 中至少一种动作的单行测试框、再回到多行框。每次记录 Return 键显示文字和实际结果。标签必须随编辑器刷新，不能保留上一个输入框的文字；按下后执行的动作必须与标签/编辑器声明一致。若测试框提供自定义 action label/id，也要确认自定义 id 被执行；缺失 label 时不得显示字面字符串 `null`。随后重复 C5 的“活动 T9 组合 + Return”，确认仍提交原始 `64`。

### R2 Shift 回退兼容

先区分由 T9 的 `T9_ascii` 进入的 `letter` 布局，以及 `tongwenfeng` 的全拼 `default` 布局：

- 两个 T9 的 `letter` 布局都没有显式 `double_click`：`trime.yaml` 的 `T9_ascii` 在第 861 行选择 `letter`，`letter` 第 1119–1123 行继承 `default`，实际 Shift 在第 1083 行；`tongwenfeng.trime.yaml` 的 `T9_ascii` 在第 4007 行选择 `letter`，其独立 `letter` 块始于第 1167 行，实际 Shift 在第 1198 行。分别验证单击/长按的既有语义；快速双击不得凭已回退的全局功能额外生成 Caps Lock。
- 另将 `tongwenfeng` 切到全拼/`default` 布局作控制。该布局第 1149 行才显式声明 `double_click: Shift_L3`，而 `Shift_L3` 在第 4042 行声明 `shift_lock: click`；这里只应继续执行主题显式双击锁定动作，并按实际主题行为解除。
- 上述布局均输入实际大小写字母，并在切换输入框/返回 T9 后检查 Shift 状态没有意外泄漏。双击必须是无其他探测插入的两次真实快速触摸，不能用两次慢单击代替。每条结果记录当时实际布局名和可见按键定义，不能把 `tongwenfeng.default` 的控制结论套到 T9 `letter`。

### R3 按键反馈按需初始化

先记录实体设备实际可用且本次启用的能力：系统按键音、振动、自定义音效、按键朗读、提交朗读及 TTS 引擎/语言。对可用能力执行下列对应步骤；无法提供或无法感知的子项记 `BLOCKED` 并说明原因，不能记 PASS，也**不会单独把全部九键核心验收判为失败**。最终由维护者明确接受或拒绝该未覆盖范围。

1. 声音、振动、按键朗读、提交朗读全部关闭后冷启动输入法并键入，确认无对应反馈且输入功能正常。
2. 对设备实际可用的系统按键音、振动、按键朗读和提交朗读分别开启；每类至少输入 5 次，记录首次初始化是否有延迟，以及稳定后是否一键一次、无重复、无崩溃。TTS 初始化期间快速输入时允许只朗读最新请求，但不能在输入框结束后朗读旧内容。没有可用 TTS 引擎时，将两项朗读记为 BLOCKED 并交维护者裁定范围。
3. 若项目提供自定义按键音，开启后等待资源就绪再连续测试；音量为 0 或关闭时应静音。切换音效后确认使用新音效且没有重复播放。
4. 在朗读/音效初始化附近快速切换输入框、隐藏键盘、切换到其他输入法再切回。旧输入框的排队朗读不得在边界后泄漏；返回 Trime 后新反馈仍可用。
5. 记录所用 TTS 引擎、语言、系统音量、振动设置及自定义音效名称，以便复现。

### R4 方案切换后的锁定布局恢复（核心必测）

本用例验证 `b14a2f1e` 的方案布局锚点修复。每一步都使用不含私人数据的新测试输入框；方案身份以重新打开**公开方案选择器后的勾选标签**为准，布局身份以指定编辑器中实际可见键盘为准。相同 QWERTY 不能代替 checked-label 证明。每次方案部署都等待实际完成和候选可用，不能只等固定秒数。

对 `tongwenfeng` 和 `trime` 两个内置主题分别完整执行：

1. 在新普通编辑器从 **朙月拼音九键**（`luna_pinyin_t9`）开始，经公开方案选择器选择 **朙月拼音**（`luna_pinyin`）；重新打开选择器，记录勾选标签。
2. 打开另一个独立的新普通编辑器，确认仍是全拼 QWERTY，不得恢复旧 T9 锁定布局。
3. 依次打开新整数编辑器、新邮箱编辑器、新普通编辑器：整数框必须显示强制数字布局；邮箱框输入并提交精确小写字面 `a`；普通框用全拼输入 `ni` 并选择精确 `你`。每个框都记录可见布局、方案勾选标签、最终文本和证据文件。
4. `trime` 主题还必须从 `luna_pinyin` 经公开选择器切换到 **朙月拼音·简化字**（`luna_pinyin_simp`）。两者会命中同一个 `qwerty`，所以必须重新打开选择器并看到勾选标签精确为 **朙月拼音·简化字**；不能凭键盘外观判 PASS。随后在该方案重复“整数框 → 邮箱框精确字面 `a` → 新普通框全拼 `ni` 选择精确 `你`”。
5. 最后经公开选择器选择 **朙月拼音九键**，重新打开选择器并记录其勾选标签；再打开独立的新普通编辑器，用 T9 依次锁定 `ni`、`hao` 并选择精确 `你好`。不得沿用前一编辑器或旧方案的组合。

任一步出现方案标签与目标不符、新普通编辑器恢复旧锁定布局、整数/邮箱强制布局返回空或陈旧锚点、字面 `a` 变成组合、`你`/`你好` 不精确、重复提交、私有 `~` 泄露、白屏或崩溃，保存首个现场并判 FAIL。两主题和 `trime` 的同 QWERTY 子路径都必须有终态；缺证据的核心路径不得记 PASS。

## 7. 收尾判定

- 核心必测范围为旧 17 项及 R1、R2、R4；每项只能填 `PASS`、`FAIL` 或 `BLOCKED`，任何未解释的核心 FAIL/BLOCKED 都必须交负责人处理。

- 单台设备通过只代表表中记录的型号、Android/API、ABI、APK SHA 和证书；不得扩大为所有真机、所有 OEM、所有 ABI 或全部 Android 版本通过。
- 最终记录必须保留候选身份、设备信息、失败材料、数据恢复状态、测试者签名和时间。本文及空模板本身不构成真机通过证据。
