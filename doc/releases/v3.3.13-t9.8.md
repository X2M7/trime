# Trime v3.3.13-t9.8 / T06 稳定版（发布草稿）

**待验：Build5 的既有功能矩阵通过，但 Android 5.0/15 数字键盘的空格键显示完整
方案名并被硬裁切，未获最终验收。数字键盘标签修复与实际字形、按键行为回归已准备；
Build6 尚未构建，稳定版尚未发布。**

最新检查点：Build5 的 API21 七项探针、17 个独立应用检查点、降级重试和导航均通过；
API35 功能验收记录继续保留。真实发布 t9.6 ARM64 → Build5 覆盖安装保留 53 字节
独立标记，转译 ARM 环境的 engine/T02 两项诊断通过；旧版初始部署未完成，不能
声称旧版已能中文输入。新应用区间未出现超过 2 秒的队列警告；这不替代 Build6
验收，也不证明历史性能风险全部消除。资源修改后的 host4 仍为 102 项通过。

本版集中修复输入框切换、键盘生命周期和部署恢复问题，继续保留九键拼音、
音节锁定、中间编辑、撤销，以及默认关闭的 T05 模糊音和数字键纠错设置。

## 修复内容

- 待 Build6 验收：数字键盘的空格键改用现有“空格”标签，避免长方案名在窄键位
  被裁切；保持原有空格按键事件，并补充实际字形可见性与按键行为回归。
- 根据输入框类型切换临时 ASCII 或数字布局；返回聊天框时恢复用户选择的
  九键方案、布局和输入模式。密码不会进入最近提交记录或语音反馈。
- 物理键盘在密码、邮箱和数字等受限输入框中直接交由 Android 编辑器处理，
  避免软键盘未显示时仍沿用中文引擎模式。
- 回车的显示和实际动作遵循同一策略，区分发送、搜索、下一项、自定义动作
  与普通换行，尊重输入框的 `NO_ENTER_ACTION` 设置。
- 为每个编辑器连接分配独立标识；旧连接的排队按键、候选点击、预编辑和
  提交结果不能写入新输入框。隐藏键盘会取消长按和连发。
- 主题对话框、选项开关和弹出菜单保留请求时的编辑器标识；切换输入框后，
  延迟完成的对话框或过期菜单回调不能影响新输入框。
- 修复消息缓冲区溢出时可能丢失提交文本或按键的问题，改用 64 帧有界缓冲和
  工作线程背压。故障通知在调度锁外发送，避免慢消费者阻塞并发调度。
- 第三方主题缺少九键、ASCII、数字或符号布局时使用内存中的内置兼容布局；
  切换方案会清理旧方案持有的布局锁，不重写用户主题文件。
- 引擎启动时显示可输入的数字键盘；部署失败后提供重试和系统输入法切换。
  只有当前方案的词典实际加载成功后才使用已有资源恢复，避免误报部署成功。
- 修复 Android 5.0 预编辑触摸浮层过早显示引发的 `BadTokenException`：
  等待锚点附着、可见且完成布局，分离后清理浮层及待显示状态，并处理失效窗口令牌。
  锚点或祖先隐藏时也会关闭浮层，同一编辑器再次显示键盘时恢复保留的预编辑。
- 修复构建时间使用秒数时在“关于”和设备信息中显示为 1970 年的问题；
  构建阶段统一转换为毫秒并校验输入。
- 修复横屏大字体下右侧候选注释裁切，以及多行剪贴板编辑内容
  在按返回键隐藏键盘后覆盖确定、取消按钮的问题。
- 为通知权限对话框补充 Activity 生命周期管理与可见窗口检查，
  处理配置变化销毁页面时对话框未关闭造成的 `WindowLeaked`。

完整开发过程、失败记录与验收边界见 [T06 验证报告](../../script/quality/VALIDATION-T06.md)。

## 签名警告与验证范围

现有 APK 的 v1/v2 签名检查通过，但 v1 检查仍报告三项 `META-INF` 覆盖警告：

- `org/jetbrains/kotlinx/kotlinx-serialization-core-jvm/verification.properties`
- `services/kotlinx.coroutines.CoroutineExceptionHandler`
- `services/kotlinx.coroutines.internal.MainDispatcherFactory`

Android 5/6 使用 v1；Android 7 及以上支持覆盖 APK 内容的 v2 签名。
保留 ServiceLoader 文件以维持协程运行和异常处理行为。最终附件仍须核对这三项
警告并保留签名报告，不能将编译无警告或 Lint 通过表述为全部安全风险消除。
请从本 fork 的发布页下载，并使用随附 `SHA256SUMS` 核对文件。
参见 [Android APK v2 签名说明](https://source.android.com/docs/security/features/apksigning/v2)。

最终可用的设备证据限于模拟器及在 x86_64 上转译运行的 ARM64 APK；没有物理设备。
模拟器验收不覆盖 ARM64 真机性能、所有 OEM 编辑器或物理 16 KB 页设备。
静态 ZIP/ELF 对齐不等同于 16 KB 设备运行验证。此前 ARM 转译环境中的启动排队
及慢帧记录仍需单独测量，不能由功能验收推断已消除。系统及故障注入日志按原样保留。
Build5 的 WebView renderer 3667 保留 Chromium `code -1` 诊断；同一时段系统记录
`isolated not needed` 终止及 Zygote 正常退出码 0，Trime 主进程继续完成 100 次循环。
结合测试销毁 WebView 的顺序，将该事件判断为测试收尾关联诊断；原始诊断未删除。
历史 Build3 renderer 2965 则记录 signal 9，不能混用两次退出状态。`FrameTracker`
超时、丢帧及 `SurfaceComposerClient` 事务警告仍保留，不能把功能通过表述为所有
警告或性能问题均已消除。

同一编辑器内隐藏、显示键盘可以保留组合与锁定状态；旋转、编辑器重启或进程
重启可能取消尚未提交的组合。分屏测试在窗口切换后显式隐藏、重新聚焦编辑器。
