## 实现范围

- 六组独立模糊音开关与三类独立数字纠错开关，默认全部关闭。
- 模糊规则在当前词典的规范字母音节上执行，再经过当前 schema 的拼写代数生成数字索引。
- 误触只搜索一次相邻键替换、漏按补入或相邻重复删除；不使用 QWERTY 相邻字母规则。
- 原有精确/补全拼音列表优先，新增建议附结构化来源，不读取候选注释作为协议。
- 点选纠错拼音只约束该段，保留原始数字与其他段；选汉字才提交。支持解锁、撤销及规范拼音学习。
- 最多查看当前段起始的 7 个编码单位、增加 32 项建议。单条规则可关闭；不串联多条模糊或误触规则。
- Android 5.0 / minSdk 21 保持不变。没有导入新词典、修改第三方子模块或更新 GitHub latest。

具体协议、限制及复测命令见 [T05 工具说明](t05/README.md)。这是显式辅助选择，不是自动混排汉字纠错。

## 失败记录与风险

- 初次模拟器启动期间，Android 在 Provider 发布超时后杀死应用，尚未进入输入测试。
  证据：`build/t05/ui-initial-360`。不能作为 T05 通过记录。
- `build/t05/ui-warm-360` 在旧 180 秒编辑时限内未跑完语料，明确失败。
  已为 T05 批量测试单独设置 900 秒时限并增加进度；T02/T03 的时限保持不变。
- `build/t05/ui-geometry-initial-large` 开始时模拟器断连，未完成大字体检查。
- 首次原生驱动的性能采样与模拟器冷启动重叠，不用于性能结论。功能断言与学习验证仍有效。
- 初轮曾遇到 Kotlin 增量编译保留旧委托类，单元测试检测后使用 `-Pkotlin.incremental=false` 完整重编通过。
- 最终补编测试包时尝试排除 `generateDebugBuildConfig` 被 Gradle provider 依赖检查拒绝。
  改用项目已有的固定 `BUILD_TIMESTAMP` 正常执行依赖后通过，应用 APK 未重新生成或篡改。
- 最终模拟器首次向导中发生一次应用 ANR，记录为等待 NEXT 的触摸事件 5005 ms。
  `build/t05/pruned-startup-dropbox.txt` 显示主线程在 ART `ConditionVariable::WaitHoldingLocks` / 输入事件收尾，
  CPU pressure some avg10=86.30、memory pressure some avg10=40.46，系统 TTS 占用 44% CPU。
  这些数据支持高负载环境是影响因素，但不能据此证明唯一根因。原生测试当时也在该模拟器运行。
  已保存异常，停止原生测试后仅重启应用、重新选择 IME，没有清除数据；部署完成后才单独执行输入测试。
  该记录不能作为启动验收通过，低内存冷启动稳定性仍需专门复测。

## 隔离与限制

模拟器使用只读、无快照会话，双核、2 GiB；没有清空个人词库。首次安装通过正常向导选择应用专属存储。

最终部署 schema 与系统资源校验和为 `build/t05/deployed-pruned.schema.yaml`、`build/t05/deployed-pruned.sha256`。
缓存复用不能视为全新部署速度。Gradle 与模拟器没有同时运行。

初轮软件渲染、ARM64 转译及调试日志影响延迟，不能外推真机性能；API 21 仅保留构建兼容性，尚未做本轮运行验证。
普通精确候选不混入修正结果，故恢复率指“显式选拼音后可选到目标汉字”，不等于自动汉字 Top-1。
若已有补全能恢复同一目标，保留补全来源，不重复计算为新规则收益。
