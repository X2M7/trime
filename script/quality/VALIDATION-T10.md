当前状态：实现已整合，第三轮完整构建通过，699 项应用 JVM 测试、213 项宿主检查、Debug／Release Lint（0 问题）通过，构建日志未发现警告。两种 ABI 的 Release 静态审核通过。但第三轮设备测试 APK 缺少独立的升级验收入口，不能用于最终设备验收。清单修正已通过实际合并检查，仍须重新构建和运行设备验收；GitHub 同步未完成。候选版本为 `3.3.13-t9.13`，本记录不将其称为已发布稳定版。

## 实现范围

- 全拼与九键的默认学习库均为 `luna_pinyin`。常用短语使用共享的 `custom_phrase.txt`；字母编码和数字编码是独立记录，不自动转换。
- 用户词库及常用短语支持导入、导出和备份恢复。修改前创建精确文件备份并校验 SHA-256；失败回滚，启动时恢复未完成的操作。每个目标保留最近三份备份，未完成操作的备份受保护。便携 Rime 快照是合并记录，精确恢复是替换记录，两者在界面中区分。
- 候选置顶按方案及当前原始输入隔离，最多保存 512 条规则，仅在前 144 项中查找目标。排序改变原生候选菜单，触摸、空格及数字选择使用同一顺序；恢复排序仅删除当前输入的置顶规则，保留学习记录。隐私模式不应用或修改置顶。
- 忘记此词提供成功请求或失败反馈。它移除学习记录，系统词典中的同词仍可能出现；不是永久屏蔽，也不会删除手动置顶。
- 候选首选突出，注释可配置，常用候选条横向滑动为默认关闭的可选功能。展开列表按快照记忆位置，分页保持每批 48 项、驻留上限 144 项。长候选使用省略显示及全文阅读入口，不无限缩小字体。
- 候选触摸在按下时记录快照和原生索引，刷新重绑后取消手势；Rime 接口仍在单线程中拒绝过期快照。
- 选择和忘记接口在 Kotlin 与 JNI 两层拒绝负索引，避免无效索引触发大量惰性候选读取；JNI 使用异常边界处理正常索引路径中的原生错误。普通 UI 未发现负索引可达路径，不将其描述为已发生的崩溃。

Android 探针包括真实 JNI 学习和候选选择、原生重启、隐私隔离、512 条置顶容量、持久化写失败、短语编辑和缓存更新、物理恢复日志及成功快照合并。它们的执行结果将在实际构建和设备运行后记录。升级验收必须使用已发布 t9.12 的旧 APK，学习后正常覆盖安装新 APK，核对 UID、文件和逻辑学习记录；单次重启不称为 APK 升级。

最终复核发现直接调用选择／忘记 API 时部分负索引可能被扩展为巨大原生索引。完整构建第一轮主动停止，收据与原始日志保留在 `build/t10/build1`，没有产生可验收 APK。新增 Android 探针对真实 200 行菜单执行 36 项负索引拒绝断言，核对快照、候选顺序和提交状态不变；这些新增断言尚未在设备执行。

第二轮的 699 项 JVM、Debug Lint（0 问题）和两 ABI 原生编译通过，但设备测试 APK 编译发现旧浮层测试仍把新的手势容器当作 TextView 读取。已改为查找实际显示的子 TextView，保留原生候选文本、物理点击和准确一次提交断言；第二轮失败日志保留在 `build/t10/build2`，不能作为完整构建通过的证据。

第三轮完整构建保存在 `build/t10/build3`，宿主检查保存在 `build/t10/host2`，Release 独立静态审核保存在 `build/t10/static2/independent-review.json`。升级预检在启动模拟器前发现测试 APK 版本字段为空，随后实际清单检查发现升级 runner 缺失；原始失败记录保存在 `build/t10/api21-run1`。测试 APK 的空版本字段允许按实际情况记录，主 APK 仍要求完整版本身份。
