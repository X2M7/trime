## 修复范围

- Rime 原生库从 Kotlin 类静态初始化移到 `rime-main`，避免创建 API/Activity/IME 时在主线程加载原生库。
- 向导的存储、输入法启用/选择状态在 IO 线程查询，页面、按钮和暂停回调使用同一份状态。
- 连续刷新请求合并，不因频繁请求而一直丢弃结果；存储切换使在途旧结果失效。
- 存储权限释放/索引清理移出主线程；程序刷新单选框不再触发存储切换；取消协程不会当作导入失败释放权限。
- 应用启动的后台同步任务调度移到 IO 线程。
- 独立字母模糊变换共享一次数字投影，保留来源与 spelling properties；失败或重新构建时不保留旧索引。
- 引擎 STARTING 时最后一个客户端退出，等待启动完成后再次检查并关闭；重连取消待关闭任务，避免遗留无客户端的引擎或误关新客户端。
- Rime 原生日志最低级别设为 WARNING，保留警告和错误，不再逐条打印预设词库及查询的 INFO/DLOG。

这是对确定的阻塞路径和索引计算的修复，不能由代码修改本身断言上轮 ANR 的唯一根因已证明。
上轮 ANR 日志仍保留在 [原始 T05 报告](VALIDATION-T05.md)，不得删除或改标成通过。

## 失败记录与边界

- 早期 Lint 在 FIR/OverdrawDetector 分析 SetupActivity 时内部异常；当时源文件在分析期间改动过，
  但没有唯一根因证明。没有通过 suppression 隐藏该异常；固定源码独立重跑已通过。
- 中间 APK `533dfeadd132...` 的首次词库部署探针达到 300 秒测试超时。期间 5960 次主线程心跳、
  最大间隔 155 ms，不能把超时写成 ANR；发现 442720 行逐条预设词库日志，已降低日志级别。
  最终复测复用了系统编译缓存，不能拿两个运行的时间差证明全新部署加速。
- 第一台临时模拟器曾出现 System UI 未响应对话框；与上一轮记录的 Trime SetupActivity ANR
  分开保存，不改称 Trime 的新失败或已修复证明。
- 当前没有真机、API 21 运行实测，保留最低版本只证明构建约束未提高。
- SAF 本轮只重跑隔离 provider 和 Trime provider，未重新取得系统文件选择器持久授权，
  不能推断所有真实设备、云盘或第三方文档提供器的兼容性。
- 未实现更广泛的异步 READY 关闭/重部署状态机；本次修复集中于原生加载、向导状态和 STARTING 退出。
- 运行日志并非零警告：仍有启动/首次显示期间 Rime 队列等待（退出探针 21795 ms，UI 探针
  8351/7631 ms）、原生桥/图形后端告警，以及 KeyCode 对 `(){Left}` 等文本宏的错误级日志和
  `SPAN_EXCLUSIVE_EXCLUSIVE` 空范围提示。后两类在原 T05 日志中也存在，本次未改变相关行为，
  尚不能认定它们完全无害。保留原日志，后续需分别定位，不通过全局屏蔽警告隐藏问题。
- 这里不是“所有 bug 已消除”的承诺；首次索引开销、全新部署耗时和不同设备 ANR 仍需后续专项验证。
